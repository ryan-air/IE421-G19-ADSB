# Fall 2025 Baseline: Measured Results

Generated by `bench/legacy/run.sh`. The unmodified Fall 2025 pipeline (Python streamer → Postgres → Node API → 2 s map poll) is fed synthetic traffic through readsb in real time. Every position it shows is matched to the transmitted frame it came from using the generator's ground truth. Method and caveats: [bench/legacy/README.md](../../legacy/README.md).

Environment: Linux 6.10.14-linuxkit, 8 CPUs (Docker), Python 3.12.3, Node v18.19.1, readsb version: 3.16.21 wiedehopf git: v3.16.21 (committed: Sun Nov 1 12:57:32 2026 0000). 120 s of traffic per run, seed 2025, repo `2e9373c`. The first 20 s of each run are excluded as warm-up.

## Notes

- **Lower bound on the real system:** Postgres runs locally, not on Supabase across the internet, so production latencies were higher.
- **Browser column:** estimated by adding the map's uniformly distributed 0–2 s poll wait to the measured API latency. Browser rendering time is not included.
- **Probe resolution:** the database and API probes poll every 100 ms, which adds about 50 ms on average.
- **Laptop numbers:** CPU and the throughput limit depend on the machine. Rerun on the benchmark host for the final report.
- **readsb output buffering:** defaults, as on a stock receiver: `--net-json-port=<ports> TCP json position output listen port / TCP server, sends one line with a json object containing aircraft details for every position received (default: 0) (consider raising --net-ro-size to 8192 for less fragmentation if this is a concern) --net-ro-size=<size> TCP output flush size (maximum amount of internally buffered data before writing to network) (default: 1280) --net-ro-interval=<seconds> TCP output flush interval in seconds (maximum delay between placing data in the output buffer and sending)(default: 0.05, valid values 0.0 - 1.0) --net-ro-interval-beast-reduce=<seconds> TCP output flush interval in seconds for beast-reduce outputs (default: value from --net-ro-interval, valid values 0.0 - 1.0)`
